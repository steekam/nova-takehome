# AI log

- **Tools:** Codex and web research against official LiteLLM, Langfuse, OpenTelemetry, and Grafana documentation. Used to create the initial pnpm workspace structure, starter web/API files, shared lesson-plan schema, initial Drizzle schema, architecture notes, and reviewer checklist.
- **Mistake caught:** The first explanation presented the brief's AI-generation boundary as my design choice. The user asked for verification; I checked the PDF and corrected the wording. The brief specifies retrieval plus LLM generation, followed by teacher editing and curriculum-lead review; it does not request AI during review.
- **Mistake caught and corrected:** An initial schema stored embeddings as JSONB to avoid a PostgreSQL extension. After reviewing the retrieval design and the user's pgvector requirement, I replaced it with PostgreSQL `vector(384)`, enabled the extension in a migration, and added a pgvector-enabled local Postgres image. The API now retrieves with BGE-small and pgvector; the playground keeps its own internal cache and evaluation path.
- **Workflow decision:** Treat lesson plans as a state machine. The API locks the plan row, applies only declared transitions, versions every edit, and blocks submit until schema, duration, and citation checks pass. A lead return needs actionable feedback; a returned edit moves the plan back to Draft and requires resubmission.
- **Integration mistakes caught:** The first live UI pass found stale curriculum endpoint paths and a JSON content type on an empty submit POST. I aligned the paths with Nest routes and only set JSON content type when a request has a body. The lead panel also tried to refetch a plan after its review decision; it now clears that selection when the plan leaves the submitted queue.
- **Provider smoke:** The first Baseten/LiteLLM app call returned invalid plan content. The API correctly saved no draft. I relaxed citation validation to allow a relevant subset of retrieved chunks while requiring the selected outcome, clarified the prompt, and added one bounded correction attempt. A later synthetic DeepSeek run through the managed prompt and LiteLLM alias passed deterministic checks; provider behavior remains model-dependent. This audit's browser and database workflow runs used the no-key mock.
- **Observability choice:** Keep LiteLLM for routing and spend, Langfuse for prompt/LLM evaluation context, and OpenTelemetry as the telemetry contract. A Collector fans out traces to Tempo and Langfuse; do not export the same proxy trace to Langfuse twice.
- **Boilerplate reference:** API plumbing patterns (Fastify setup, error handling, request logging/IDs, Swagger, throttling, security headers, multipart, telemetry lifecycle, and reusable CRUD concepts) were adapted from [MarkNjunge/nest-boilerplate](https://github.com/MarkNjunge/nest-boilerplate). The local Collector, Tempo, Prometheus, Loki, and Grafana wiring follows its observability setup. Its CRUD implementation is TypeORM-specific; Nova's persistence primitives use typed Drizzle operations and leave ownership and workflow rules to domain services.
- **Environment configuration:** Added Varlock with a committed `.env.schema`, `.env.local` overrides, and startup validation before API instrumentation. Root `pnpm dev` injects validated config into both apps; Drizzle config uses Varlock directly.
- **Curriculum-library scope:** Keep the current web library browse-and-inspect only. Seeds and imports populate hierarchy, immutable source revisions, provenance, and readiness. Document upload, extraction, lead approval, indexing, and publication remain a proposed extension.
