# Retrieval evaluation

Run `pnpm playground -- retrieval-eval` to embed eight paraphrased queries with local BGE-small and rank all nine fixture chunks before mandatory-source pinning. It compares three document-side representations against the same frozen queries and labels: raw chunk text; title and type plus raw text; title and type plus text with the repeated synthetic banner removed. It also compares raw-text BGE ranking with BM25 over raw chunk text and reciprocal-rank fusion of both. RRF fuses the top five dense results with up to five positive-scoring BM25 results, using a constant of 60; documents outside the fused candidate set receive no vote. Original chunk text remains unchanged for prompts, grounding, and citations. Reports include full rankings, representation hashes, model/revision and pipeline identifiers, corpus and label-set hashes, cache counts, elapsed time, and metrics under `.cache/playground/retrieval-evals/`. The default revision is `main` to reuse the local Transformers.js cache; set `EMBEDDING_MODEL_REVISION` to an immutable commit for reproducible model artifacts. The configured revision is part of each vector cache key.

Each query uses graded labels: `2` directly answers the query, `1` is useful secondary support, and `0` does not answer that intent. A zero does not mean the source is bad. Labels describe one KICD target plus eight synthetic support chunks in the particle fixture; they do not verify the wider CBC curriculum.

The report includes macro and per-query **nDCG@3** (graded ranking), **grade-2 Hit@1**, and **grade-2 Recall@3**. Grade 1 means useful secondary support; only grade 2 counts as a direct-answer hit. It also compares two maximum context sizes after pinning the target, lead notes, and fixture-designated teaching and assessment evidence: top 6 selects six chunks; top 8 selects eight. Each case records selected IDs and grade-2 coverage for both policies. Reports include vector cache hits/misses, model load time, warm pipeline reuse count, and total elapsed time. A CLI process keeps one local BGE feature-extraction pipeline warm, avoiding repeated model loads during the query set. Do not compare mock-embedding reports with BGE scores. These paired experiments use a small, synthetic-heavy fixture; eight queries cannot establish a production model or policy. Review per-query rank changes, then add held-out queries and real CBC sources before choosing an embedding model or retrieval policy.

Current eight-query text-only BGE ranking run: mean nDCG@3 `0.6707`, Hit@1 `0.625`, Recall@3 `0.8125`. The end-of-lesson assessment passage ranked fifth. The selected-context policy now pins that passage and the lesson's focus evidence before filling remaining slots by rank; rerun the evaluation to refresh policy-coverage results.

The paired representation run left text-only as the default: title/type plus raw content scored nDCG@3 `0.4754`, grade-2 Hit@1 `0.5`, grade-2 Recall@3 `0.5`; title/type plus stripped banners scored `0.4883`, `0.25`, and `0.75`. The additions hurt the primary ranking metrics on this fixture, so metadata is not added to embedded text. BM25 on raw chunk text scored nDCG@3 `0.6045`, grade-2 Hit@1 `0.5`, grade-2 Recall@3 `0.75`; dense+BM25 RRF scored `0.5927`, `0.5`, and `0.75`. The hybrid underperformed dense overall and did not fix the closing-assessment rank. Under the current selection policy, text-only BGE reached grade-2 coverage `1.0` at top 6 and top 8; the metadata representations reached `0.75`/`1.0` and `0.75`/`0.875` at top 6/top 8. This is a small, fixture-specific result, not a broad CBC retrieval claim. Keep dense BGE as the current default while improving query intent and corpus coverage, then rerun with held-out CBC sources.

On this workstation, the latest fresh cache namespace took `1.999s`, including `367ms` to load BGE; the pipeline was reused for the other 23 rankings. The run generated 51 vectors and reused 189 cached vectors. A second run with the same revision took `43ms`, reused all 240 vectors, and skipped model loading. These timings depend on hardware and a locally cached model; use the JSON report fields for tester-machine measurements. The `main` revision can move upstream, so pin a commit when reproducibility matters and use a new cache namespace after changing the model or revision.
